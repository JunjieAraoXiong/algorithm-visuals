Token Bucket Rate Limiter 令牌桶限流器

允许短暂突发，同时限制持续请求速率。参考 Alex Xu 第 4 章。

请求与令牌

一个用户的一种请求

先确定按谁、按哪个接口限流，避免把所有人的请求混进同一个桶。

先限定一个用户的一种请求

以 user:42 创建短链接为例。允许短时突发，但不能让一个用户持续占满服务；每个请求消耗一个令牌。

key = user:42 + POST /api/links
capacity = 3
refill = 1 token / second

代价与边界

数值是演示选择。身份来自已验证的用户或密钥，不应直接信任客户端随意提交的 user ID。

容量与速率分别控制什么

容量决定空闲后积攒的突发额度；补充速率决定长时间内可持续通过的速率。

令牌桶允许短时间超过补充速率，不能理解成“每一个一秒窗口最多放行一条”。这里以整秒补充和顺序请求演示；生产实现还需决定时间精度、计费权重与失败策略。

扩到多台网关时

同一个用户的额度必须有一致的归属。

若每台网关各存一个满桶，总额度会随实例数放大。可以路由到同一个限流分区，或使用共享存储做原子补充与消费；共享存储的延迟、故障和热点也随之进入设计。
