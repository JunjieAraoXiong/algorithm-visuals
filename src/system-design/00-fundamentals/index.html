步骤 1 / 16

先分清请求里的几个词

一次用户操作可能产生多个网络请求；一个 API 请求也可能访问多个内部组件。

DNS / IP / Port
DNS 把域名解析成地址；IP 用来寻址，端口标识主机上接收连接的服务端点。DNS 缓存可省去重复查询。
HTTP / HTTPS
HTTP 定义请求与响应的语义，例如 GET、POST、状态码和正文。HTTPS 用 TLS 保护传输；不替代应用层身份验证与权限检查。
TCP / TLS / 连接复用
图中用新建 HTTP/1.1 + TLS 连接说明建立连接的成本。已有连接可以复用；HTTP/3 使用 QUIC，不按这条 TCP 建连路径执行。
同步 / 异步
同步路径上，调用方等待结果。异步任务可以先返回“已接收”，之后再查询完成状态；接收成功不代表工作已经完成。

每种组件解决一个具体问题

先测量延迟、流量、错误和饱和度，再选组件。这些是可组合的工具，不是每个系统的必选清单。

Client + API / 谁发起，谁处理

做什么
客户端发出操作；API 定义可调用的接口。服务端验证身份与权限、执行业务逻辑，再返回状态码与数据。
何时需要
只要浏览器或 App 需要访问共享业务数据，就要明确这个边界。一个服务端进程可以提供许多 API。
代价 / 边界
API 是约定，server 是运行代码的进程或机器；两者不是同一个概念。用户输入不能直接当成可信权限。

Database + Index / 保存与查找

做什么
数据库组织持久数据，执行查询与更新。索引是为某类查找建立的额外结构，可减少扫描的记录数。
何时需要
先确定数据长什么样、如何查询、哪些更新必须一起成功，再选择结构与索引。
代价 / 边界
索引占空间并增加写入维护；事务的原子性保证一组操作全成或全败。持久性、一致性和备份各有不同职责。

Cache + Database / 副本与事实来源

做什么
缓存保存可以重新获取的结果。Cache-aside：API 先查缓存；未命中再查数据库，把结果写入缓存。
何时需要
重复读取多、数据库读压力高，而且能说清哪些内容允许缓存、多久可以过期。
代价 / 边界
命中率低时帮助有限；缓存可能过期或失效。写入后如何更新或删除缓存必须明确，不能把缓存当唯一持久记录。

Load balancer + 实例 / 分发与执行

做什么
负载均衡器选择实例；多个 API 实例运行相同应用。无状态实例把持久业务与会话状态放到共享存储，仍可有请求内临时变量。
何时需要
测量发现 API 的 CPU、并发或单机故障风险已成为约束；先确认后面的数据库能接住新增流量。
代价 / 边界
LB 不复制数据，也不让数据库变快。单个 LB 仍可能故障；健康检查、容量和部署策略都要覆盖。

Queue + Worker / 保存任务与处理任务

做什么
队列保存等待处理的任务；worker 从队列领取任务并执行，成功后确认。用户可先得到任务 ID，之后查看结果。
何时需要
邮件、导出、缩略图等允许延后完成的工作，或需要缓冲短时突发。
代价 / 边界
常见投递机制允许重复；worker 必须安全去重。还要处理积压、失败重试和无法完成的任务。队列不创造处理能力。

CDN + Object storage / 分发与保存原件

做什么
对象存储按 key 保存图片、视频、附件等字节；CDN 把可缓存内容放在靠近用户的边缘节点。对象存储可以是 CDN 的源站。
何时需要
文件较大、用户地理分散，或文件流量占用应用服务资源。元信息与权限仍可由 API 和数据库管理。
代价 / 边界
对象存储不是通用关系查询；CDN 也不是原始存储。私有内容授权、缓存失效、回源与流量成本都需要权衡。

Replica + Partition + Backup / 三种目的

做什么
复制把同一批记录保存多份；分区把不同记录分到不同节点。备份保留可恢复的历史，以便从误删或损坏中恢复。
何时需要
分别对应冗余 / 读取能力、数据量 / 写入分担、历史恢复。一个分区也可以有自己的副本和备份。
代价 / 边界
副本可能延迟，也可能复制误删；分区引入跨分区操作与数据迁移。恢复流程必须实际验证，复制不等于备份。

怎样判断下一步加什么

沿着一次请求找到实际瓶颈，并检查增加组件后，数据与故障会怎样变化。

数据库慢，先检查查询、索引与扫描量；重复读取才考虑缓存。API 计算饱和，考虑优化或增加实例。文件传输占用资源，考虑对象存储与 CDN。允许延后的工作，才移入队列。任何一次扩展，都要重新检查下游容量。

平均延迟会掩盖慢请求；p95 表示约 95% 的观测请求不超过该延迟。可用性也需要明确定义：哪些请求、观察多久、何种响应算成功。一次压测或一张结构图都不能替代这些测量。
