Replicated Key-Value Store 副本读写

写入等几个确认，读取等几个响应，怎样影响返回的版本？

同一个 key，三个版本位置

固定 N = 3

固定 A、B、C 三个副本，初始都保存 theme=light 的 v0。

先固定副本集合与写入顺序

只讨论一个 key、一个写者和一次 v0 到 v1 的更新。三个副本身份不变，版本有确定的先后关系。

key = theme
v0 = light
v1 = dark
N = 3

代价与边界

这是固定副本的确定性模拟，不包含并发写、成员变更、故障替代副本或真实网络。

步骤 1 / 17

确认数改变等待的边界

W 是写入成功前等待的确认数；R 是读取返回前等待的响应数。

本例请求发往固定三副本。W=1 时 A 确认就返回，B 的写消息尚未处理。W≥2 时继续等 B。C 的写消息在读取完成前不会到达；延迟场景下 C 仍能先响应读取，离线场景下它不能响应。超时不能证明写入没有发生。

交集条件需要哪些前提

R + W > N 只说明两个固定集合必定相交。

对已获 W 个确认的写入，本例还假设副本不丢失已确认版本、读取发生在写确认之后、没有并发写，并从 R 个响应中选最大版本。真实系统的线性一致性还涉及并发、版本顺序、故障和协议；不能只凭这条不等式判断。

补上恢复协议

本例由协调者保留 v1，并在读完后补齐延迟副本。
