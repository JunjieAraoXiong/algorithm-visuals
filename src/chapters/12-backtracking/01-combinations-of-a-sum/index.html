Combinations of a Sum · 组合总和

Given an integer array and a target value, find all unique combinations in the array where the numbers in each combination sum to the target. Each number in the array may be used an unlimited number of times in the combination. Example: nums = [1, 2, 3], target = 4 → [[1,1,1,1],[1,1,2],[1,3],[2,2]].给定正整数数组 nums（元素互不相同）和目标值 target，找出所有和为 target 的组合；每个数字可以无限次使用，输出不得包含重复组合——[1,1,2] 与 [1,2,1] 视为同一个组合。书例：nums = [1, 2, 3]，target = 4，答案是 [[1,1,1,1],[1,1,2],[1,3],[2,2]]。

完整 Python 代码

def combinations_of_sum_k(nums: List[int], target: int) -> List[List[int]]:    res = []    dfs([], 0, nums, target, res)    return resdef dfs(combination: List[int], start_index: int, nums: List[int], target: int, res: List[List[int]]) -> None:    # Termination condition: If the target is equal to 0, we found a combination    # that sums to 'k'.    if target == 0:        res.append(combination[:])        return    # Termination condition: If the target is less than 0, no more valid    # combinations can be created by adding to the current combination.    if target < 0:        return    # Starting from 'start_index', explore all combinations after adding    # 'nums[i]'.    for i in range(start_index, len(nums)):        # Add the current number to create a new combination.        combination.append(nums[i])        # Recursively explore all paths that branch from this new combination.        dfs(combination, i, nums, target - nums[i], res)        # Backtrack by removing the number we just added.        combination.pop()

圆圈内是剩余 target，圆圈下方是当前 combination；连线上标的是这一步选的数。左侧面板是 combination 栈（向上增长），中间是 nums 与 start_index 候选区，右侧是已收集的 res。

直觉：把 target 当剩余额度 / Remaining budget

数组全是正数，所以组合和只会单调增长：和一旦达到 target 就不可能再变小，超过就永远超过。这给出两条终止条件——剩余 target 恰好等于 0，当前组合就是一个答案；小于 0，此路超支，直接剪掉。因为正数保证单调，剪枝不会剪掉任何正确答案。

实现上不必维护 sum 变量：直接把 target 当“剩余额度”，选中 nums[i] 就以 target - nums[i] 递归，额度一路扣减；回溯时 combination.pop() 撤销选择，额度随递归栈自然恢复。

无限次使用：传 i 不传 i+1

0-1 背包式回溯递归传 i + 1（每个数至多一次）；本题允许复用，所以传 i——同一个数下一轮仍可以被选，[1,1,1,1] 由此产生。

答案要复制 combination[:]

combination 是全程共享的可变列表，之后还会被 pop 修改。res.append(combination) 只存引用，必须 combination[:] 复制一份快照，否则 res 里全是空列表。

为什么 start_index 能去重 / Why no duplicates

重复的来源：同一个组合有多个“生成顺序”。[1,3] 可以先选 1 再选 3，也可以先选 3 再选 1——若每个位置都允许任选数字，两者都会进 res。去重的关键不是事后用集合过滤，而是统一表示：规定每个组合按 nums 的顺序排列，靠 start_index 强制执行——当前组合以 nums[i] 结尾，下一轮就只能从 nums[i] 及之后选数，永不回头。于是 [1,2,1] 这类乱序版本根本不会被生成，[1,3] 与 [3,1] 只剩字典序最小的那一个。

边界情况 / Edge cases

target 恰好用尽

剩余 target 精确减到 0 才收答案；少一分都不行。如 [1,3]：1+3=4 收，1+3 之后再选任何正数都会变负被剪。

提前为负

只要剩余 target < 0 就立即返回，不再尝试任何候选——正数不可能把和“减回来”。这就是剪枝帧里整棵子树被标红的原因。

nums 含 1 时递归最深

每轮至少选最小候选 m，树高至多为 target / m。nums 含 1 时达到最深：书例中 [1,1,1,1] 一路递归到第 4 层，这也是空间复杂度的来源。

无解

若 target 小于 nums 中最小的数（如 nums=[2,3]，target=1），每个分枝第一步就超支，res 为空列表 []——代码无需特判。

复杂度 / Complexity

Time · O(ntarget/m)

m 为 nums 中最小的候选数。树高至多为 target / m（每轮至少扣掉 m），每层最多 n 个分枝，状态树结点数上界 ntarget/m；每个结点只做 O(1) 的 append/pop 与常数次判断。

Space · O(target/m)

递归栈深度至多为 target / m（nums 含 1 时取到），combination 最长同样这么长；不计输出 res 的话，额外空间就是 O(target/m)。
