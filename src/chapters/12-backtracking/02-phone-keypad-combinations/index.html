Phone Keypad Combinations · 电话号码字母组合

You are given a string containing digits from 2 to 9 inclusive. Each digit maps to a set of letters on a traditional phone keypad: 2: abc, 3: def, 4: ghi, 5: jkl, 6: mno, 7: pqrs, 8: tuv, 9: wxyz. Return all possible letter combinations the input digits could represent. Example: digits = "69" → ["mw","mx","my","mz","nw","nx","ny","nz","ow","ox","oy","oz"].给定只含 2–9 的数字串，每个数位对应传统电话键盘上的一组字母，返回所有可能的字母组合。书例：digits = "69"，答案是 ["mw","mx","my","mz","nw","nx","ny","nz","ow","ox","oy","oz"]——共 3×4 = 12 个。

完整 Python 代码

def phone_keypad_combinations(digits: str) -> List[str]:    keypad_map = {'2':'abc','3':'def','4':'ghi','5':'jkl','6':'mno','7':'pqrs','8':'tuv','9':'wxyz'}    res = []    backtrack(0, [], digits, keypad_map, res)    return resdef backtrack(i: int, curr_combination: List[str], digits: str, keypad_map: Dict[str, str], res: List[str]) -> None:    # Termination condition: if all digits have been considered, add the    # current combination to the output list.    if len(curr_combination) == len(digits):        res.append("".join(curr_combination))        return    for letter in keypad_map[digits[i]]:        # Add the current letter.        curr_combination.append(letter)        # Recursively explore all paths that branch from this combination.        backtrack(i + 1, curr_combination, digits, keypad_map, res)        # Backtrack by removing the letter we just added.        curr_combination.pop()

curr_combination 是根到当前节点的路径（左起第 0 位 = 数位 0 的选择）；树上实心节点 = 已收集进 res 的叶子，粗线 = 当前路径。

直觉：每个数位一个决策 / One decision per digit

把 "69" 翻译成字母的过程，是一连串二选一……不，一连串“三/四选一”：先决定数位 0 的 '6' 到底代表 m、n 还是 o；每个选择之下，再决定数位 1 的 '9' 代表 w、x、y 还是 z。两个决定拼起来就是一个组合。于是整个搜索空间天然是一棵树：根是空串，第 i 层对应第 i 个数位的候选字母，走到 i == n 的叶子就得到一个完整组合。

这棵树很小（3×4 = 12 个叶子），但结构是通用的：数位变长、键位变多，树只是等比例放大——n 个数位、每数位最多 4 个字母时，叶子数最多 4n。回溯的任务就是有条理地把这棵树走一遍，不重不漏。

回溯骨架：与组合的总和完全同构 / Same skeleton

backtrack 的骨架和「组合的总和」一题一模一样：① 终止条件——len(curr_combination) == len(digits) 时把当前组合收进 res；② 枚举当前数位的所有候选字母；③ append 做选择 → 递归处理下一个数位 → pop 撤销选择，让循环继续试下一个字母。下标 i 标明每个节点正在处理哪个数位，递归调用时 i + 1 把决策权交给下一位。

为什么恰好不重不漏

第 i 层的每个节点都尝试 keypad_map[digits[i]] 的全部字母，层间用下标 i 划分决策，层内用 for 枚举全部候选——任何一条根到叶子的路径唯一对应“每个数位各选一个字母”的方案，DFS 恰好访问每个叶子一次。

本题没有剪枝

组合的总和里 sum > target 的分枝会被剪掉；本题任何部分组合都能补完成合法答案，所以树上的每条路径都会走到叶子——你看到的 15 次 pop 全部发生在收集之后或层间切换时，没有一次是“白走”。

变量与链接的分工

curr_combination 是递归栈上的“当前路径”，由 append/pop 维护；res 只在叶子处追加、从不删除。树边的粗细只是路径的可视化，真正的状态变化只发生在这两个列表上。

面试提示 / Interview tip

keypad_map 这种琐碎又耗时的映射实现，可以问面试官“能否先写占位、稍后补全”，但至少口头说明它的形式：一个 digit → letters 的哈希表，查询 O(1)。

边界情况 / Edge cases

空串 digits = ""

书中未约定。右侧实现原样执行会得到 [""]：backtrack(0, []) 一进入就满足 0 == 0，空组合被收进 res（这也是 LeetCode 的约定）。若你的面试官要求返回 []，在入口处加一个 if not digits: return [] 特判即可。

含 7 或 9：4 分枝

'7' → 'pqrs'、'9' → 'wxyz' 是仅有的两个四字母键，其余数字键都是 3 个字母。分枝因子不均匀不影响代码——for 循环读的总是 keypad_map[digits[i]] 的真实长度。

单个数位

digits = "6"：根节点一层直接终止，答案是 ["m","n","o"]——每个候选字母自己就是一个完整组合。树的“第 1 层”同时是叶子层。

重复数位

digits = "22"：两个数位独立决策，["aa","ab","ac","ba","bb","bc","ca","cb","cc"] 共 9 个。同一键可被多个数位引用，keypad_map 只存一份。

复杂度 / Complexity

Time · O(n·4ⁿ)

状态树高 n，分枝最多 4（7 和 9 四字母），叶子（组合）数最多 4n；每个组合 "".join(curr_combination) 要 O(n)。更精确的写法是 O(n·Π len(keypad_map[d]))，d 取遍 digits 的每个数位。

Space · O(n)

递归栈最深 n 层，curr_combination 里最多 n 个字母；keypad_map 是 8 项常数表。按书的约定，输出 res（共 4n 个串）不计入。
