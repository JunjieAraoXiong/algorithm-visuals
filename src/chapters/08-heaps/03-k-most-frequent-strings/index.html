K Most Frequent Strings · 前 K 个高频字符串

Given strs = ["go", "coding", "byte", "byte", "go", "interview", "go"] and k = 2, return the k most frequent strings sorted by frequency in descending order. If two strings have the same frequency, sort them in lexicographical order.给定字符串数组 strs 和整数 k（k ≤ n），返回出现次数最多的前 k 个字符串，按频率从高到低排列；频率相同按字典序排列。例：strs = ["go", "coding", "byte", "byte", "go", "interview", "go"]，k = 2，答案 ["go", "byte"]。

完整 Python 代码 · 大顶堆

两个实现共用同一组名字：Pair、freqs、res。小顶堆的 Pair.__lt__ 把不等号全部反转，让优先级完全倒过来。

直觉：先计数，再挑出前 k 个 / Count first

不知道频率就无从比较。先用哈希表 freqs 扫一遍数组：键是字符串，值是出现次数。之后两种堆方案面对的都只是 n 个不同的 (str, freq) 对。

排序的浪费 / Sorting everything

把 n 个字符串按频率倒序排序再取前 k 个是 O(n log n)。但答案只有 k 个——为 k 个答案给全部 n 个字符串排序并不划算，堆可以把代价压到 O(n log k)。

并列谁在前 / Tie-breaking

题目要求频率相同时按字典序。比较器必须同时编码两条规则：频率高者胜出；频率相等时，字典序小者胜出。两条规则分别写在 __lt__ 的两个分支里。

解法一：大顶堆 · O(n + k log n)

每次拿走当前最频繁的一个字符串，剩下的堆顶自然变成下一个——连续 pop k 次就得到答案。建堆不必逐个 push（O(n log n)），用 heapify 对所有 (str, freq) 对一次性自底向上调整，只要 O(n)。

heapify · O(n) 建堆

heapq.heapify(max_heap) 从最后一个父节点 i = n // 2 - 1 往上到 0，把每个父节点与它更优先的孩子比较，需要时下沉。例中 freqs.items() 的顺序恰好已满足堆性质，所以一次也没交换。

自定义比较器 / Pair.__lt__

return self.freq > other.freq：频率高者"更小"、排在堆顶；self.freq == other.freq 时 return self.str < other.str：字典序小者优先。比如 (coding, 1) 与 (interview, 1) 并列时，coding 胜出。

一次 heappop 做了什么

取下堆顶 [0] 作为返回值；把最后一个叶子移到 [0]；再让它沿“更优先的孩子”一路下沉，直到不比孩子差。下沉最多走树高 O(log n) 层。

正好 k 次

for _ in range(k) 只循环 k 次，堆里剩下的 n - k 个 Pair 不再参与。总计 O(n) + k · O(log n) = O(n + k log n)。

解法二：大小为 k 的小顶堆 · O(n log k)

堆里只留 k 个候选。每 push 一个新对，若堆大小超过 k，堆顶就是当前第 k+1 频繁的字符串——把它弹出，堆立刻恢复到 k 个。

为什么弹出是安全的 / Safe to evict

被弹出的那一刻，堆里剩下的 k 个字符串频率都不比它小；继续扫描只会让这些频率增大，所以它们最终也不比它小——这个字符串注定进不了前 k。

比较器反转 / Inverted comparator

小顶堆的 __lt__ 把不等号全部反转：self.freq < other.freq，并列时 self.str > other.str。频率相等时，字典序大的反而排在堆顶、先被弹出，留下的都是字典序小者。

取出后要 reverse

小顶堆先弹出的是第 k 频繁、最后弹出的才是第 1 频繁，所以 res 里是反的，返回前执行 res.reverse()。例中弹出 [byte, go]（freq 2 → 3），反转后才是 [go, byte]。

为什么不能用大顶堆做同样的事

要丢弃"当前最小"就必须能读到它：大顶堆只能访问最频繁者，拿不到最不需保留的那个，所以只能改用维护小顶堆。

两种方法都需要 O(n) 的 freqs 哈希表（最多存 n 个不同的字符串）；输出数组 res 不计入空间复杂度。当 k 远小于 n 时，小顶堆的 O(n log k) 明显优于大顶堆的 O(n + k log n)，也优于完整排序的 O(n log n)。

边界情况 / Edge cases

k = n

每个字符串都要返回。小顶堆的大小永远不会超过 k，不会触发任何弹出；最后弹出全部 n 个再 reverse。

频率全部相同

顺序完全由字典序决定：比较器的并列分支是唯一裁决者，两种方法都返回字典序最小的 k 个。

并列发生在切分线上

例中 coding 与 interview 同为 1 次且 k = 2，两个都进不了前 2。若某个并列者被弹出而另一个是答案，比较器保证字典序小者留下。

只有一个不同字符串

freqs 只有一项，k 必为 1：两种方法都直接返回它，堆操作退化为常数。
