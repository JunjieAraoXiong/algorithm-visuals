Sort a K-Sorted Array · K 有序数组排序

Given an integer array where each element is at most k positions away from its sorted position, sort it in non-decreasing order. Example: nums = [5, 1, 9, 4, 7, 10], k = 2 → [1, 4, 5, 7, 9, 10].给定整数数组 nums，每个元素距离它在完全有序数组中的位置最多 k 个位置（灰色虚线行只是参考——算法开始时我们并不知道它）。请把数组按非递减顺序排序。例：nums = [5, 1, 9, 4, 7, 10]，k = 2，输出 [1, 4, 5, 7, 9, 10]。

完整 Python 代码

import heapq def sort_a_k_sorted_array(nums: List[int], k: int) -> List[int]:    # Populate a min-heap with the first k + 1 values in 'nums'.    min_heap = nums[:k+1]    heapq.heapify(min_heap)    # Replace elements in the array with the minimum from the heap at each    # iteration.    insert_index = 0    for i in range(k + 1, len(nums)):        nums[insert_index] = heapq.heappop(min_heap)        insert_index += 1        heapq.heappush(min_heap, nums[i])    # Pop the remaining elements from the heap to finish sorting the array.    while min_heap:        nums[insert_index] = heapq.heappop(min_heap)        insert_index += 1    return nums

heapq 是小顶堆：min_heap[0] 永远是当前候选中的最小值，恰好就是 insert_index 位置上该写的数。

直觉：答案总在附近 / The answer is nearby

直接排序要 O(n log n)，它无视了「几乎有序」这个条件。换个方向想：一个数在有序数组里属于 index i，它在 k 有序数组里一定落在 [i − k, i + k] 内——每左移或右移一格，离正确位置的距离最多变化 1。反过来更实用：index 0 的答案只可能藏在 nums[0..k] 里；归位它之后，index 1 的答案只可能藏在接下来前 k+1 个值里，依此类推。每个位置要写的，只是某个「滑动窗口」里的最小值。

  1. index 0 在有序数组里放的是全局最小值，所以它一定是 nums[0..k] 的最小值。
  2. 归位 index i 后，index i+1 的候选窗口右移一格：[i+1, i+1+k]——已归位的左侧不再考虑。
  3. 窗口每次只挪一格：去掉一个已写出的旧候选、补上一个新候选。重复求窗口最小值成为唯一的热点，交给小顶堆。

小顶堆：窗口最小值的快速通道 / Min-heap as the fast lane

每次在一个大小不超过 k+1 的集合里取最小值，正是小顶堆的看家本领：堆顶 O(1) 读取，push / pop 各 O(log k)。先 heapify 前 k+1 个值，之后每写出一个最小值，就把 nums[i] 补进堆——窗口随 i 右移，堆大小在主循环里恒为 k+1，收尾阶段逐次减小。

朴素做法 · O(nk)

每个位置都线性扫一遍 [i, i+k] 找最小值，最多比较 k+1 个候选。k 接近 n 时退化为 O(n²)——和直接排序一样差。

堆优化 · O(n log k)

heapify 用 O(k) 建堆；主循环执行 n − k 次，每次一次 heappop 加一次 heappush，各 O(log k)。k 越小，优势越大。

堆为什么恰好够用

任意时刻，堆里装的正是「下一个待写位置的候选窗口」中尚未写出的值：一个不多、一个不少。堆顶即窗口最小值，直接就是 insert_index 位置的答案。

heapify 还是逐个 push

对 k+1 个值，heapq.heapify 自底向上调整只要 O(k)；逐个 heappush 是 O(k log k)。两者代码都短，建堆选 heapify 更优——这也是书中的写法。

为什么原地覆写是安全的 / Why overwriting in place is safe

nums[insert_index] = heapq.heappop(min_heap) 直接覆盖原值：被覆盖的数会不会是后面某个位置的答案？不会——它一定早已进了堆。主循环里 i = insert_index + k + 1 恒成立：insert_index 要追到 i 至少还需 k+1 步，而任何数离它的排序位置最多 k 步，所以 nums[i] 被覆写之前必先被 push 进堆。更本质的不变量：堆中恰好装着下一个待写位置的全部候选。

不变量

每次 heappop 之前，堆 = 候选窗口中未写出的值。堆顶不大于窗口内任何值，正是 insert_index 位置该写的数——写出后窗口右移，不变量保持。

指针关系

每轮循环：先 pop 写出（insert_index 指向的位置），再 insert_index += 1，最后 push nums[i]。写出一个、补进一个，堆大小回到 k+1。

图里的有序行只是参考

书中的插图把排好序的数组画在旁边，帮助理解每个数离目的地有多远；算法开始时我们并不知道它，整个过程也从没构造过这个有序数组。

重复值与负数

堆只按大小比较：重复值任意先写后写都不破坏非递减顺序；负数与正数走完全相同的逻辑，无需特判。

边界情况 / Edge cases

k = 0 · 已经有序

堆只装 1 个元素：heapify 是 O(1)，每次 pop / push 也是 O(1)（log 1 = 0），全程 O(n) 顺手验证数组已有序。代码无需任何特判。

k ≥ n − 1 · 退化为堆排

nums[:k+1] 取到整个数组，主循环一次都不执行，只剩逐个 heappop 写回——等价于 heap sort，O(n log n)。

空数组 / 单元素

nums[:k+1] 与原数组相同，循环边界天然兼容，直接返回原列表。

k 大于数组长度

nums[:k+1] 自动截断到整个数组，行为和 k ≥ n − 1 完全一致，不会越界。

复杂度 / Complexity

heapify · O(k)

对 k+1 个元素自底向上调整，比较与交换次数与 k 成正比。

主循环 · O((n − k) log k)

n − k 次迭代，每次 heappop + heappush 各 O(log k)（堆大小恒为 k+1）。

收尾 · O(k log k)

drain 阶段从堆中弹出剩余 k+1 个值依次落位，各 O(log k)。

总计 · O(n log k)

O(k) + O((n − k) log k) + O(k log k) = O(n log k)。k ≪ n 时远优于完整排序的 O(n log n)。

空间 · O(k)

堆最多同时保存 k+1 个元素；排序在原数组上原地进行，不分配额外数组。
