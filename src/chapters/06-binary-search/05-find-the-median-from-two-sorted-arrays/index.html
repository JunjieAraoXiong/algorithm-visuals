Find the Median From Two Sorted Arrays · 两个有序数组的中位数

Given two sorted integer arrays, find their median as if they were merged into a single sorted sequence. Example: nums1 = [0, 2, 5, 6, 8], nums2 = [1, 3, 7] → 4.0, because the merged array [0, 1, 2, 3, 5, 6, 7, 8] has median (3 + 5) / 2; with nums2 = [1, 3, 7, 9] the median is 5.0. At least one array is non-empty. 给定两个有序整数数组，求它们合并成一个有序序列后的中位数。例：nums1 = [0, 2, 5, 6, 8]、nums2 = [1, 3, 7] → 4.0（合并后 [0, 1, 2, 3, 5, 6, 7, 8]，中位数为 (3 + 5) / 2）；若 nums2 = [1, 3, 7, 9]，中位数是 5.0。约束：至少一个数组非空。

Final Python / 最终代码

def find_the_median_from_two_sorted_arrays(nums1: List[int],                                           nums2: List[int]) -> float:    # Optimization: ensure 'nums1' is the smaller array.    if len(nums2) < len(nums1):        nums1, nums2 = nums2, nums1    m, n = len(nums1), len(nums2)    half_total_len = (m + n) // 2    left, right = 0, m - 1    # A median always exists in a non-empty array, so continue binary search until    # it's found.    while True:        L1_index = (left + right) // 2        L2_index = half_total_len - (L1_index + 1) - 1        # Set to -infinity or +infinity if out of bounds.        L1 = float('-inf') if L1_index < 0 else nums1[L1_index]        R1 = float('inf') if L1_index >= m - 1 else nums1[L1_index + 1]        L2 = float('-inf') if L2_index < 0 else nums2[L2_index]        R2 = float('inf') if L2_index >= n - 1 else nums2[L2_index + 1]        # If 'L1 > R2', then 'L1' is too far to the right. Narrow the search space        # toward the left.        if L1 > R2:            right = L1_index - 1        # If 'L2 > R1', then 'L1' is too far to the left. Narrow the search space        # toward the right.        elif L2 > R1:            left = L1_index + 1        # If both 'L1' and 'L2' are less than or equal to both 'R1' and 'R2', we        # found the correct slice.        else:            if (m + n) % 2 == 0:                return (max(L1, L2) + min(R1, R2)) / 2.0            else:                return min(R1, R2)

虚线切片和 L1 / R1 / L2 / R2 chip 都只是变量引用：二分过程只改下标变量，nums1 和 nums2 从头到尾没有被修改。/ The slices and chips are variable references only; the two arrays are never modified.

从合并到一刀切 / From merging to a single slice

最直白的做法是把两个数组合并再取中位数：两个数组各自有序，顺序归并只要 O(m + n)，但题目想要的是 O(log) 级别。观察合并后的数组：中位数只取决于正中间的一两个值，而它们又只由“在哪里切一刀”决定——所以不必真合并，只要找到那个切分位置。/ Merge first is only O(m + n), but we can do better: the median depends only on the one or two middle values of the merged array, which are fixed by where we slice. So search for the slice instead of merging.

  1. 合并数组总能切成两半：总长为偶数时各半 (m + n) / 2 个值，中位数就来自两半区内侧的两个值——左半区的最大值和右半区的最小值。/ Even total: each half holds (m + n) / 2 values; the median is the mean of the inner-edge pair.
  2. 所以真正要决定的只有一件事：哪些值属于左半区、哪些属于右半区。/ So the only real question is which values belong to the left half and which to the right.
  3. 左半区的大小已经知道（half_total_len），未知的只是每个数组各出几个值——这正是要搜索的东西。/ The left half's size is known up front (half_total_len); what we search for is how many values each array contributes.

候选切片很多，正确的只有一个 / Many slices, one correct

左半区必须恰好装 half_total_len 个值，但满足“大小”的切法有很多种。以交换后的 nums1 = [1, 3, 7]、nums2 = [0, 2, 5, 6, 8] 为例（总长 8，左半区 4 个值），下面三种切法大小全对，却只有一种是合并数组真正的两半：/ The left partition must hold exactly half_total_len values, but many cuts satisfy that size. With the swapped nums1 = [1, 3, 7], nums2 = [0, 2, 5, 6, 8] (total 8, left half 4), all three cuts below have the right size — only one is the merged array's true halves.

切法一 · nums1 出 3 个

大小对了，但 L1 = 7 大于 R2 = 2：左半区里混进了本该在右半区的值。/ Right size, but L1 = 7 exceeds R2 = 2: a right-half value leaked into the left.

切法二 · nums1 出 0 个

nums1 一个不出时 L1 越界，取 -∞；但这次 L2 = 6 大于 R1 = 1，还是错。/ With nums1 contributing nothing, L1 is out of bounds and becomes -∞; but now L2 = 6 exceeds R1 = 1.

切法三 · 各出 2 个 ✓

L1 ≤ R2 且 L2 ≤ R1 同时成立：左半区每个值都 ≤ 右半区每个值。/ Both L1 ≤ R2 and L2 ≤ R1 hold: every left value ≤ every right value.

判据只有一句话：左半区的每个值都必须 ≤ 右半区的每个值。由于每个数组内部有序，段内比较（L1 ≤ R1、L2 ≤ R2）天然成立，会出问题的只有交叉的两对：L1 ≤ R2 和 L2 ≤ R1。越界时用 -∞（左段空）或 +∞（右段空）占位，比较自动成立。/ The test: every left value ≤ every right value. Internal comparisons (L1 ≤ R1, L2 ≤ R2) are free because each array is sorted; only the two crossings L1 ≤ R2 and L2 ≤ R1 can fail. Out-of-bounds boundary values become -∞ / +∞.

只在 nums1 上二分 / Binary search on the smaller array

四个边界值里只要定下 L1_index，其余三个都能推出来：L2_index 由 half_total_len 反推，R1 / R2 就是 L1 / L2 右边一格。于是问题变成“在 nums1 里二分 L1_index”：猜一个位置、检查两个交叉比较、不对就按方向收缩。开头的交换保证 nums1 是较短数组，搜索空间最多 log(min(m, n))。/ Once L1_index is chosen, the other three boundary values follow: L2_index is forced by half_total_len, and R1 / R2 sit one step right of L1 / L2. So binary-search L1_index inside nums1 — guess, check both crossings, narrow. The initial swap keeps nums1 the smaller array, capping the search space at log(min(m, n)).

L1 > R2 → 向左收缩

nums1 左段有值超过了 nums2 右段的最小值，说明切片太靠右：right = L1_index - 1。上方「演示 · 切片太靠右」里连续收缩了两次，最后 L1_index = -1，nums1 左段为空、L1 取 -∞。/ A nums1 left value exceeds the smallest nums2 right value: the slice is too far right, so right = L1_index - 1. In the first demo trace this fires twice, ending at L1_index = -1 with L1 = -∞.

L2 > R1 → 向右收缩

nums2 左段有值超过了 nums1 右段的最小值，说明切片太靠左：left = L1_index + 1。上方「演示 · 切片太靠左」里收缩一次后 R1 越界取 +∞，比较自动通过。/ A nums2 left value exceeds the smallest nums1 right value: the slice is too far left, so left = L1_index + 1. In the second demo trace this happens once, after which R1 = +∞.

奇数总长：多出的值在右半区 / Odd totals: the extra value sits right

总长为奇数时 (m + n) // 2 向下取整，左半区比右半区少一个值——正中间的那个数落在右半区，所以中位数就是 min(R1, R2)。上方「例 2 · 奇数总长」的 trace 走的就是这条路。/ With an odd total, (m + n) // 2 rounds down: the right partition holds one extra value, and the median is min(R1, R2) — the middle value of the merged array. The second example trace follows this path.

书中的提醒 / A note from the book

max(L1, L2) 与 min(R1, R2) 只是用来计算中位数的两个值，它们本身并不是“中位数”；奇数总长时甚至只需要 min(R1, R2) 一个值。也不要把这个切片误会成“两个数组各自的中位数”——它是合并数组的切分位置。/ max(L1, L2) and min(R1, R2) are merely the pair used to compute the median — they are not themselves "medians"; with an odd total, only min(R1, R2) is used. Nor is the slice related to each array's own median: it is the split position of the merged array.

边界情况 / Edge cases

nums1 为空

交换后 nums1 仍是较短数组（m = 0），left = 0、right = -1，第一轮 L1_index = -1 → L1 = -∞、R1 = +∞，代码一行不改。如 nums1 = []、nums2 = [1, 2, 3] → 2.0。/ After the swap nums1 is still the shorter one (m = 0): left = 0, right = -1, first round L1_index = -1 → L1 = -∞, R1 = +∞. No special case needed.

重复值

所有比较都是 ≤ / >：相等不会误判。交叉比较通过就意味着整个左半区 ≤ 右半区（含相等）。/ All comparisons are ≤ / >, so equal values never break the checks; passing both crossings means left ≤ right with equality allowed.

负数

-∞ / +∞ 只是越界占位符，与真实值比较不受影响；负数走完全相同的逻辑（演示 2 的输入里就有 0）。/ The infinities are out-of-bounds placeholders only; negative numbers flow through the identical logic.

while True 会死循环吗

不会。中位数必然存在（至少一个数组非空），±∞ 占位保证每次检查都有确定结论，搜索区间每轮严格缩小，必然收敛到正确切片——这就是书里用 while True 的原因。/ No: the median always exists, the ±∞ guards make every check decisive, and the search interval shrinks strictly each round, so the loop always reaches the correct slice — the book's reason for while True.

复杂度 / Complexity

Time · O(log min(m, n))

只在较短的数组上二分 L1_index：每轮一次交叉检查，排除约一半候选位置；nums2 的切分由 half_total_len 直接推出，从不遍历。/ Binary search runs only over the smaller array: one crossing check per round eliminates half the candidates; nums2's slice is derived, never scanned.

Extra space · O(1)

只保存 m、n、half_total_len、left、right 和四个边界值变量；两个输入数组从头到尾不被修改。/ Only a constant number of index and boundary-value variables are stored; both input arrays are left untouched.
