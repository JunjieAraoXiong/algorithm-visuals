First and Last Occurrences of a Number · 数字的首尾出现位置

Given a non-decreasing array, return the first and last index of target, or [-1, -1] if it is not found. nums = [1, 2, 3, 4, 4, 4, 5, 6, 7, 8, 9, 10, 11], target = 4 → [3, 5].

完整 Python 代码 / Final Python

def first_and_last_occurrences_of_a_number(nums: List[int],                                           target: int) -> List[int]:    lower_bound = lower_bound_binary_search(nums, target)    upper_bound = upper_bound_binary_search(nums, target)    return [lower_bound, upper_bound] def lower_bound_binary_search(nums: List[int], target: int) -> int:    left, right = 0, len(nums) - 1    while left < right:        mid = (left + right) // 2        if nums[mid] > target:            right = mid - 1        elif nums[mid] < target:            left = mid + 1        else:            right = mid    return left if nums and nums[left] == target else -1 def upper_bound_binary_search(nums: List[int], target: int) -> int:    left, right = 0, len(nums) - 1    while left < right:        # In upper-bound binary search, bias the midpoint to the right.        mid = (left + right) // 2 + 1        if nums[mid] > target:            right = mid - 1        elif nums[mid] < target:            left = mid + 1        else:            left = mid    # If the target doesn't exist in the array, then it's possible that    # 'left' = mid + 1' places the left pointer outside the array when    # 'mid' == n - 1'. So, we use the right pointer in the return    # statement instead.    return right if nums and nums[right] == target else -1

数组本身不被修改；每一步只移动 left / right / mid 三个下标变量。/ The array never changes; each step only moves the three index variables.

思路：把“找首尾”拆成两个二分 / Two binary searches

一次标准二分命中某个等于 target 的下标后，无法知道它是不是第一个或最后一个。而相等的值在非递减数组里连成一块，所以只要分别锁定这块的左端点和右端点。两个搜索的中点规则几乎一样，唯一区别是 nums[mid] == target 时的收缩方向，以及上界搜索的 mid 要右偏。

上界 · upper_bound_binary_search
123434445567891011

找最右一个 nums[i] <= 4 的下标 → 5。命中 4 时保留 mid（left = mid），区间持续向右靠。

调试死循环：mid 为什么要右偏 / Why mid is biased right

上界搜索里有 left = mid 这个操作。如果 mid 用 (left + right) // 2 向下取整，当区间只剩两个元素时 mid 会落在 left 上，left = mid 什么也没改变，循环永远停在原处。把 mid 改成 (left + right) // 2 + 1 后，两个元素的区间里 mid 落在 right 上；而 right 只接受 right = mid - 1，不会再指向自己，区间必然缩小。

错误：mid 向左取整
left mid right 4 4 4 5

mid = (4 + 5) // 2 = 4，nums[4] == 4 → left = mid = 4。下一轮 mid 仍是 4，区间 [4, 5] 不再缩小 → 无限循环。下界搜索没有这个问题，因为它的操作是 right = mid，而 mid 向左取整时永远不会等于 right。

修正：mid = (left + right) // 2 + 1
left mid right 4 4 4 5

mid = (4 + 5) // 2 + 1 = 5，nums[5] == 4 → left = mid = 5。此时 left == right，循环结束，返回 5。right = mid - 1 不会把 right 指回自己，所以右偏后不会再卡住。

边界情况 / Edge cases

target 不存在 · 返回 [-1, -1]

两个搜索结束时都要校验：nums[left] == target / nums[right] == target，不满足就返回 -1。例如 target = 12，两个搜索分别收拢到端点 12，nums[12] = 11 ≠ 12，主函数返回 [-1, -1]。

空数组 · nums = []

nums and ... 先判空，短路掉对 nums[0] 的访问，空数组直接返回 -1，不会越界。

target 只出现一次 · [6, 6]

例如 target = 7：下界与上界收拢到同一个下标 6，校验都通过，返回 [6, 6]——首尾可以是同一位置。

返回值为什么用 right 而不是 left

上界搜索里 left = mid + 1，而 mid 最大能到 n - 1；若 target 大于所有元素，left 会变成 n 越界。循环结束时 right 一定在数组内，所以返回语句检查的是 nums[right]。

复杂度 / Complexity

时间 · O(log n)

lower_bound_binary_search 与 upper_bound_binary_search 各做一次二分，搜索区间每次约减半，合计仍是 O(log n)。

额外空间 · O(1)

只保存 left、right、mid 三个下标变量，不使用额外数据结构。

面试提示 / Interview tip

写完二分一定要手动测试。上界搜索里的死循环在设计时很容易漏掉；测一个只含两个元素的搜索空间（比如本题的 [4, 5]）就能暴露它——这正是在推导中遇到死循环的那一步。
