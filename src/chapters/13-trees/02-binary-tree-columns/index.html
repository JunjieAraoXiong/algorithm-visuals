Binary Tree Columns · 二叉树的垂序遍历

Given the root of a binary tree, return a list of arrays where each array represents a vertical column of the tree. Nodes in the same column should be ordered from top to bottom. Nodes in the same row and column should be ordered from left to right. Example: the tree below returns [[2],[9],[5,1,4],[3],[7]].给定二叉树根节点，按“竖直列”输出整棵树：同一列的节点自上而下排列；同一行又同一列的节点从左到右排列。书例如下，答案是 [[2],[9],[5,1,4],[3],[7]]——注意 5、1、4 同处第 0 列：5 是根在最上，1 和 4 同行，1 在左先出现。

完整 Python 代码

def binary_tree_columns(root: TreeNode) -> List[List[int]]:    if not root:        return []    column_map = defaultdict(list)    leftmost_column = rightmost_column = 0    queue = deque([(root, 0)])    while queue:        node, column = queue.popleft()        if node:            # Add the current node's value to its corresponding list in the hash            # map.            column_map[column].append(node.val)            leftmost_column = min(leftmost_column, column)            rightmost_column = max(rightmost_column, column)            # Add the current node's children to the queue with their respective            # column ids.            queue.append((node.left, column - 1))            queue.append((node.right, column + 1))    # Construct the output list by collecting values from each column in the hash    # map in the correct order.    return [column_map[i] for i in range(leftmost_column, rightmost_column + 1)]

圆圈内是节点值；节点下方的 col = … 是它的列编号，五条竖色带即列 −2…+2。下方左侧面板是 queue（队首在左，null 条目是虚线格），右侧五个槽位是 column_map 按列号的排布（入桶顺序即自上而下），旁边常显 leftmost / rightmost。

直觉：给每个节点一个列编号 / Column id

把根放在第 0 列：每向左走一步列编号 −1，向右走一步 +1。于是一条竖直线上的所有节点同列——9 在 −1 列，2 在 −2 列，1 和 4 都落在 0 列，7 在 +2 列。遍历每个节点时把它的值丢进哈希表 column_map[column] 对应的桶里，分列就完成了。

哈希表本身无序，输出却要“从左到右按列”。代码用一对边界变量解决：leftmost_column / rightmost_column 在遍历中记录见过的最小、最大列号，收尾时 range(leftmost, rightmost + 1) 逐个取值，顺序就有了保证。

为什么用 BFS 而非 DFS / Why BFS

题目对顺序有两条要求：同列自上而下、同行同列自左而右。BFS 逐层展开，一层之内从左到右入队——两条要求被同一种遍历顺序同时满足：层号就是自上而下的次序，每层内先入队的在左。反观 DFS 先序：它沿左枝一路扎到底，左子树里更深的节点会先于右子树里更浅的同列节点访问，本例恰好没踩雷（col 0 的 5、1、4 先序也是这个顺序），但换一个形状就会破坏“自上而下”。想让 DFS 正确，得额外记录每个节点的深度再排序，状态更多、更易错。

queue 里忠实的 null 条目

书中实现把孩子无条件入队：queue.append((node.left, column - 1)) 并不判断 node.left 是否存在。叶子的孩子是 None，于是队列里混着 (null, col) 条目，出队时靠 if node: 把它们跳过。这些 null 帧在演示里如实出现。

1 与 4 的先后：队列说了算

1 和 4 同在第 2 行、同在 0 列。9 先于 3 出队，所以 1 先于 4 入桶，[5,1,4] 里的左到右次序由 BFS 的 FIFO 自然保证，没有任何特判。

边界情况 / Edge cases

空树

if not root: return [] 在第一行就返回空列表——垂序遍历没有列可言。这是唯一的显式特判。

单列树

只有根节点时，所有节点都在 0 列，leftmost = rightmost = 0，输出 [[5]] 这样的单桶列表；range 只扫一列。

斜树

全左斜链的列号一路 −1,−2,−3…，leftmost 每层左移一格；全右斜链则 rightmost 右移。边界跟随遍历扩张，range 覆盖整段。

null 条目翻倍队列流量

每个节点入队两次（两个孩子），其中叶子贡献的全是 null。队列流量是 2n 而不是 n，但每个条目仍是 O(1) 处理，复杂度不变。

复杂度 / Complexity

Time · O(n)

每个真实节点出队一次、入桶一次、两个孩子入队一次，全是 O(1) 操作；null 条目出队即丢，也是 O(1)。总计 O(n)。

Space · O(n)

队列最宽时约为最宽层节点数的 2 倍（每个节点带一个孩子条目，书例中峰值 8 条），上界 O(n)；column_map 存全部 n 个值，O(n)。不计输出数组。
