Maximums of Sliding Window · 滑动窗口最大值

A sliding window of size k slides through an integer array nums from left to right. Return a new array recording the largest number of each window. For example, nums = [3, 2, 4, 1, 2, 1, 1], k = 4 returns [4, 4, 4, 2].一个大小为 k 的滑动窗口从左向右滑过整数数组 nums，返回新数组：依次记录每个窗口里的最大值。例如 nums = [3, 2, 4, 1, 2, 1, 1]，k = 4，答案是 [4, 4, 4, 2]。

不变量 / Invariant

left
right
res
dq（front → back）

完整 Python 代码

def maximums_of_sliding_window(nums: List[int], k: int) -> List[int]:    res = []    dq = deque()    left = right = 0    while right < len(nums):        # 1) Ensure the values of the deque maintain a monotonic decreasing        # order by removing candidates ≤ the current candidate.        while dq and dq[-1][0] <= nums[right]:            dq.pop()        # 2) Add the current candidate.        dq.append((nums[right], right))        # If the window is of length 'k', record the maximum of the window.        if right - left + 1 == k:            # 3) Remove values whose indexes occur outside the window.            if dq and dq[0][1] < left:                dq.popleft()            # The maximum value of this window is the leftmost value in            # the deque.            res.append(dq[0][0])            # Slide the window by advancing both 'left' and 'right'. The            # right pointer always gets advanced so we just need to advance            # 'left'.            left += 1        right += 1    return res

dq 的 front（左端）是队首 dq[0]，back（右端）是队尾 dq[-1]；两端都能 O(1) 增删。

直觉：只保留“候选值” / Only candidates matter

暴力做法对每个窗口重新扫一遍 k 个元素，一共 O(n·k)。问题在于相邻两个窗口共享 k - 1 个元素，却被反复重新检查。换个思路：维护一份候选（candidates）——还有可能成为某个未来窗口最大值的值；不可能再当最大值的值直接丢弃。

窗口 [3, 2, 4, 1] 里每个数的命运如下：

3

忽略下一个窗口就滑出去了

2

丢弃右边有 4：所有未来包含 2 的窗口也包含 4，2 永远赢不了

4

保留当前窗口的最大值，还会出现在未来若干窗口里

1

保留比 4 小，但 4 更靠左、先老化；4 滑出后 1 有机会当最大值

三条规则 → 单调递减 → 双端队列 / Rules to deque

窗口每遇到一个值，执行三条规则：① 从右端弹出所有 ≤ 新值的候选——它们比新值小、又比新值先进入窗口，永远不可能再当最大值；② 把新值连同下标作为 (值, 下标) 元组压入右端；③ 窗口滑动后，从左端弹出下标 < left 的过期候选。

候选永远单调递减

新值只从右端“清场”，所以 dq 自左向右始终单调递减（相等也弹出，实际是严格递减）。当前窗口的最大值因此永远是队首 dq[0]，直接读取，不用扫描。

为什么存下标

规则③靠下标判断过期：dq[0][1] < left 说明队首已滑出窗口。只存值的话，无法区分“值相同但位置不同”的候选。

为什么栈不够用

单调栈只能操作一端，而过期候选积压在左端，栈顶够不着。需要一个两端都能增删的结构——双端队列 deque，可以理解成“双端栈”，两端都是 O(1)。

面试提示 / Interview tip

不确定用什么数据结构时，先列出所需的属性与操作，再据此选型。本题的要求是“两端都能高效增删”——匹配到的就是 deque。

边界情况 / Edge cases

k = 1

每个窗口只有一个数。新值会把 dq 里 ≤ 它的旧候选全部弹出，dq 里始终最多 1 个元素，答案就是每个数本身。

k = n

只有一次记录：dq 单调递减，dq[0] 是全局最大值；其后的过期清理永远不会触发。

相等的值

比较用的是 <=，相等的候选也会被弹出：靠右的新值更晚老化，严格优于靠左的旧值，重复的候选没有存在必要。

严格递减的数组

如 [5, 4, 3, 2]：没有任何弹出，dq 一路涨到 k 个，靠规则③从左端清理——这是空间的最坏情况 O(k)。

复杂度 / Complexity

Time · O(n)

每个元素最多入队一次、出队一次（无论从哪端），每次双端操作都是 O(1)。虽然代码里有 while 循环，总代价仍是线性的。

Extra space · O(k)

dq 最多保存 k 个候选（窗口里每个位置至多一个候选）。按书的约定，输出数组 res 不计入空间复杂度。
